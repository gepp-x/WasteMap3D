## 2. Modelled gridded precipitation — ERA5 reanalysis (`public/data/{city}/rain-grid.json`)

- **Model used for every published value (both cities, grids and hourly events): `models=era5` = ECMWF ERA5 reanalysis (Copernicus Climate Change Service, C3S); 0.25° × 0.25° regular latitude/longitude grid (≈27–28 km), hourly.** RainSeries `kind: "reanalysis-grid"`, provenance `status: "estimated"`, `sourceId: "open-meteo-archive-era5"`.
- **Period**: 2024-01-01 → 2026-10-28 (1032 days). Rule: Last local (Asia/Bangkok) date in [2026-10-21, 2026-11-03] whose 24 hourly precipitation values are all non-null at both city-centre points (models=era5). Determined 2026-11-03T22:59:30.866Z; persisted in `data/raw/open-meteo/period_era5.json` so reruns are deterministic (`--refresh-period` re-probes, `--end-date=` pins). ERA5 latency: ≈5 days behind real time on Open-Meteo (the most recent ~2–3 months are the preliminary ERA5T release).
- **Why ERA5 (model decision)**:
  - `models=era5_land` (the brief's first choice): HTTP 200 but `precipitation_sum` = null for every day of the check window (confirmed). Open-Meteo does not serve ERA5-Land precipitation (ERA5-Land is forced by ERA5 precipitation).
  - `models=best_match` (the brief's fallback) compared with `models=ecmwf_ifs` and `models=era5` on 3 windows: bkk-2024-01: =IFS true, =ERA5 false (sums best_match/IFS/ERA5 2.8/2.8/1.6 mm); bkk-2025-06: =IFS true, =ERA5 false (sums best_match/IFS/ERA5 83.1/83.1/45.2 mm); hy-2025-11: =IFS true, =ERA5 false (sums best_match/IFS/ERA5 566.5/566.5/811 mm). So best_match precipitation here is the ECMWF IFS operational analysis/short-range-forecast archive (~9 km), whose model version changes over time — not a reanalysis.
  - ERA5 is a frozen-model reanalysis available for the whole period and both cities, which matches the contract's `kind: "reanalysis-grid"`. Trade-offs accepted: coarser cells (0.25°) and ~5-day latency (the period ends a few days earlier than best_match would).
- **Daily aggregation convention** (verified): Open-Meteo's daily `precipitation_sum` (timezone Asia/Bangkok) = sum of the 24 hourly values stamped 00:00–23:00 local; each hourly value is the accumulation over the preceding hour, so day D covers (D−1 23:00, D 23:00] local. Check at the Hat Yai centre (ERA5 cell 7°N 100.5°E): 2025-11-20 daily 135.9 mm vs Σhourly 135.9 mm; 2025-11-21 daily 240 mm vs Σhourly 240 mm → identical. Values rounded to 0.1 mm.
- **Grids** (regular cell-centre lattices as specified; Open-Meteo answers each coordinate with ONE model cell — no interpolation — so lattice points inside the same 0.25° ERA5 cell carry identical series):
  - Bangkok: 0.1° lattice, centres lon 100.35…100.95 × lat 13.45…13.95 (42 points), cells span [100.30, 13.40, 101.00, 14.00] ⊇ bbox [100.32, 13.49, 100.94, 13.96]. **Distinct ERA5 cells: 11**; points verified identical to their cell series: 42/42.
  - Hat Yai: bbox buffered by 0.05° → [100.38, 6.92, 100.56, 7.11]; 0.05° lattice, centres lon 100.375…100.575 × lat 6.925…7.125 (25 points). **Distinct ERA5 cells: 2** — the whole municipality falls into very few reanalysis cells, so the Hat Yai grid conveys almost no intra-city spatial variation; points verified: 25/25.
  - Fetch method (polite, deterministic): one short request with all lattice points (Bangkok 2024-09-01..14, Hat Yai 2025-11-18..27) records the cell Open-Meteo assigns to each point; the full period is then fetched once per distinct cell at the first lattice point mapped to it (same coordinates → same cell; the returned cell is checked); finally every point's short-window values must equal its cell's full-period values, otherwise the city grid is not written. Point→cell mapping, representative points and DEM elevations: `data/staged/rain-grid-meta.json`. Raw responses: `data/raw/open-meteo/cellmap_*_era5_*.json`, `grid_*_era5_cells_*.json`.

## 7. Investigation log (manual, before the script was written)

- `api-v3.thaiwater.net` has no robots.txt (HTTP 404); `www.thaiwater.net/robots.txt` allows all. The public endpoint list was read from the front-end bundle `www.thaiwater.net/dist/js/app.chunk.js` (saved as text in `data/raw/thaiwater/`, never executed).
- `weather.bangkok.go.th`: no robots.txt (404 page). The page's own popup builder maps the array columns (see §1). No hidden/authenticated API was called.
- `aeromet2.tmd.go.th`: robots.txt `Allow: /` (disallows only `/admin`, `/add-daily-data`). The public report page is a SPA; its bundle (`/assets/DailyRainfallReportPage-*.js`, `dailyObsApi-*.js`) shows the read-only endpoint `/api/daily-obs/rainfall-report`; the `unlock`/`entry` endpoints are for data entry and were not used.
- `data.tmd.go.th` open-data API: requires `uid`/`ukey` → not used. `climate.tmd.go.th`: connection reset (curl error 56). `www.tmd.go.th/en/ClimateChart` and `/en/climate/climatestat` were fetched once (HTTP 200) but contain no station normals tables.
- NOAA NCEI `pub/data/normals/WMO/1991-2020/` → HTTP 404 (the WMO 1991–2020 normals are in NCEI accession 0253808, not used because TMD's own report was found).
- Open-Meteo probes (2026-11-03/04): `models=era5_land` → precipitation null for 2024 and 2026 test periods (temperature present); `models=era5` → data ≈5 days behind real time; `models=best_match` → data to the previous day; best_match equals `ecmwf_ifs`, not `era5`. Decision: `models=era5` for all published values (see §2).
- `dds.bangkok.go.th` (about pages, flood report) contain no capacity figures. `pr-bangkok.com/?p=373537` → HTTP 404. The DDS 2569 action-plan PDF (161,119,984 bytes) was HEAD-checked but not downloaded (size).
- Hat Yai municipal drainage design intensity: searched Thai news / municipality sources — nothing verifiable found → recorded as unknown.

## 8. Caveats

- Station values are real-time snapshots at the retrieval time shown; rerunning the script without `--offline` replaces them.
- Gridded and hourly values are modelled ERA5 reanalysis (0.25°, via Open-Meteo `models=era5`), not observations and not ERA5-Land; they smooth convective extremes, carry only a few distinct cells per city (Hat Yai especially) and use local-midnight (effectively 23:00–23:00) days. The most recent months are preliminary ERA5T and may be revised.
- Normals are single-station 30-year means (Bangkok Metropolis, Hat Yai Airport ~10 km south of the municipality), not area averages.
- Drainage figures are as stated by officials/media; nominal capacities are not simultaneous effective capacities. Translations are unofficial.
- Open-Meteo free API: non-commercial use only; attribute “Weather data by Open-Meteo.com” (CC BY 4.0).
